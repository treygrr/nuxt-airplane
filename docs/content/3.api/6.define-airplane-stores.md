```ts
function defineAirplaneStores(
  stores: Record<string, string>,
  options?: { version?: number }
): AirplaneStores
```

Default-export its result from a file in the [`handlersDir`](/getting-started/configuration#handlersdir). Several files can declare stores; they are merged and the highest `version` wins.

Every type your documents select with an `id` already has a table named after it (`db.Site`), keyed on the id and typed from the schema; see [Inferred tables](/guide/stores-and-query-handlers#inferred-tables). This helper adds to that.

## Parameters

| | |
| --- | --- |
| `stores` | For an inferred table, the extra indexes: `Item: 'name'`. For a table of your own, its full definition in Dexie's [`stores()` syntax](https://dexie.org/docs/Version/Version.stores()): `'++id, siteId'`, `'[siteId+itemId], siteId'`… |
| `options.version` | Schema version, default `1`. Bump it to change an existing table's primary key. Adding tables or indexes needs no bump. |

## Typing your own tables

Inferred tables are typed for you. For a table of your own, augment the global `NuxtAirplaneStores` interface so `db.<table>` is typed in handlers:

```ts [app/airplane/stores.ts]
declare global {
  interface NuxtAirplaneStores {
    drafts: { id?: number, siteId: string, body: string }
  }
}

export default defineAirplaneStores({
  Item: 'name',
  drafts: '++id, siteId',
})
```

`db.drafts` is then a `Table<{ id?: number, siteId: string, body: string }>`.

## Reserved names

`queries`, `mutations` and `meta` belong to the module.

```ts
function useSync(): UseSyncReturn
```

## Returns

```ts
interface UseSyncReturn {
  online: Ref<boolean>
  networkOnline: Ref<boolean>
  forcedOffline: Ref<boolean>
  syncing: Ref<boolean>
  synced: ComputedRef<boolean>
  pending: Ref<MutationRow[]>
  failed: ComputedRef<MutationRow[]>
  blocked: Ref<number>
  syncTotal: Ref<number>
  syncCount: Ref<number>
  lastError: Ref<string | null>
  retryAt: Ref<number | null>
  prefetching: Ref<number>
  sync: () => Promise<void>
  rollback: (id: number) => Promise<MutationRow[]>
  dependents: (id: number) => MutationRow[]
  retry: (id: number) => Promise<void>
  goOffline: () => void
  goOnline: () => void
}
```

See [Sync and offline](/guide/sync-and-offline) for the meaning of each field. During SSR every ref is a static placeholder (`online: true`, `synced: true`, `pending: []`, `failed: []`) and the functions do nothing. On a page rendered on the server the refs keep those values until it has hydrated, so the first render matches.

`goOffline()` and `goOnline()` are [kept](/guide/sync-and-offline#the-choice-is-kept): across reloads, and in every tab.

## Example

```vue
<script setup lang="ts">
const { pending, rollback, dependents, retry, goOffline, goOnline, forcedOffline } = useSync()
</script>

<template>
  <button v-if="forcedOffline" @click="goOnline()">Go online</button>
  <button v-else @click="goOffline()">Go offline</button>

  <ul>
    <li v-for="m in pending" :key="m.id">
      {{ m.description }} <em>{{ m.status }}</em>
      <button v-if="m.status === 'failed'" @click="retry(m.id)">Retry</button>
      <button :disabled="m.status === 'syncing'" @click="rollback(m.id)">
        Roll back<template v-if="dependents(m.id).length"> and {{ dependents(m.id).length }} more</template>
      </button>
    </li>
  </ul>
</template>
```

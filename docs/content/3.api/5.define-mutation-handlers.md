```ts
function defineMutationHandlers<T>(handlers: { [N in keyof T]: MutationHandler<N, T[N]> }): MutationHandlers
function defineMutationHandler<N extends MutationName, L>(name: N, handler: MutationHandler<N, L>): MutationHandlers
```

Both give you typed keys and typed `variables`; the singular form declares one mutation by name, for one-file-per-mutation layouts, and returns a map you can spread into the plural form. Default-export the result from a file in the [`handlers.dir`](/getting-started/configuration#handlersdir). The [`handlers.generate`](/getting-started/configuration#handlersgenerate) option writes a file with empty `apply` and `reconcile` hooks for every mutation that has no handler.

## Types

Shown without the plumbing that infers `L` from the `local` object and carries it to `useMutation`. A `local` key that is also one of the mutation's variables is a type error.

```ts
interface MutationHandler<N extends MutationName, L = {}> {
  /** Local variables and their defaults: taken by `mutate`, handed to `describe`, `apply`, `reconcile` and `revert` as `local`, never sent. */
  local?: L
  /** Summary for the pending list; computed when queued, before `apply`, and again when a later mutation is merged into it. */
  describe?: string | ((ctx: HandlerContext<MutationVariables<N>, L>) => string | Promise<string>)
  /** Runs when queued, inside an undo-logged transaction. */
  apply?: (ctx: ApplyContext<MutationVariables<N>, L>) => unknown
  /** Runs with the server response after the mutation was sent. */
  reconcile?: (ctx: ReconcileContext<MutationVariables<N>, L>, result: MutationResult<N>) => unknown
  /** Runs on rollback, before the rows go back to the server's version. */
  revert?: (ctx: HandlerContext<MutationVariables<N>, L>) => unknown
  /** Folds a later mutation of the same document into one still waiting: returns the variables that stand for both, or nothing. */
  merge?: (earlier: MutationVariables<N>, later: MutationVariables<N>) => MutationVariables<N> | null | undefined | false
  /** Queries to refetch after sync. Defaults to the mounted queries that fill a table the mutation changed, or all of them when it changed none. */
  refetch?: QueryName[]
}

interface HandlerContext<V, L> {
  db: AirplaneDexie
  /** A query's result kept with `store: 'result'`, to read or change; see defineQueryHandlers. */
  result: ResultAccessor
  /** What is sent: the variables the mutation declares. */
  variables: V
  /** The handler's local variables, defaults filled in. */
  local: L
}

interface ApplyContext<V, L> extends HandlerContext<V, L> {
  /** A placeholder id for a row the server will create; stable across re-applies. */
  tempId: () => string
}

interface ReconcileContext<V, L> extends HandlerContext<V, L> {
  /** The ids `apply` minted, in call order. */
  tempIds: string[]
  /** Map a placeholder to the server's id; queued mutations are rewritten before they are sent and the row in an inferred table is re-keyed. */
  resolve: (tempId: string, id: string) => Promise<void>
}
```

`result(name, variables)` reaches the result a query keeps with [`store: 'result'`](/api/define-query-handlers): `update` it in `apply` and the change shows at once and is undone on rollback, like any other write. Its types (`ResultAccessor`, `StoredResult`) are on the [`defineQueryHandlers`](/api/define-query-handlers#types) page.

The `local` object types the local variables, at the hooks and at `mutate`; see [`local`](/guide/mutation-handlers#local). Hooks may return anything, so a Dexie call can be the whole handler. See [Mutation handlers](/guide/mutation-handlers) for when each hook runs and [Creating offline, then editing](/guide/mutations#creating-offline-then-editing) for `tempId` and `resolve`.

## Example

```ts [app/airplane/sites.ts]
export default defineMutationHandlers({
  DeleteSite: {
    describe: async ({ db, variables }) => `Delete ${(await db.Site.get(variables.id))?.name}`,
    apply: ({ db, variables }) => db.Site.delete(variables.id),
    refetch: ['GetSites']
  },
  ArchiveSite: {
    apply: ({ db, variables }) => db.Site.update(variables.id, { archived: true })
  }
})
```

All options sit under the `airplane` key of `nuxt.config.ts`.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-airplane'],
  airplane: {
    endpoint: '/api/graphql',
    schema: './schema.graphql',
    documents: ['**/*.gql', '**/*.graphql'],
    handlersDir: 'airplane',
    dbName: 'nuxt-airplane',
    codegen: {}
  }
})
```

## Options

### `endpoint`

- Default: `'/api/graphql'`

URL the client posts operations to. A relative path is resolved against the app's own origin, which is handy when the GraphQL server is a Nitro route in the same project.

### `schema`

- Default: `undefined`

Where the schema used for type generation comes from. Either a path to an SDL file or a URL to introspect. When omitted the module introspects `endpoint`.

::note
In dev a relative `endpoint` can only be introspected once the dev server is up, so the first type generation is untyped and a second one runs a moment after "Ready". The last successfully loaded schema is cached in `node_modules/.cache/nuxt-airplane/schema.graphql` and used as a fallback, so a production build without a running server still gets types.
::

### `documents`

- Default: `['**/*.gql', '**/*.graphql']`

Globs, relative to `srcDir`, of the files holding your operations. Files are watched in dev and the composables regenerate on change.

### `handlersDir`

- Default: `'airplane'`

Directory, relative to `srcDir`, scanned for [mutation handler](/guide/mutation-handlers) files. Every `.ts` / `.js` file in it is imported and its default export merged into one handler map.

### `dbName`

- Default: `'nuxt-airplane'`

Name of the IndexedDB database. Change it if several apps on the same origin use the module.

### `codegen`

- Default: `{}`

Extra configuration passed to the `typescript` and `typescript-operations` plugins of GraphQL Code Generator. The module sets `namingConvention: 'keep'` and types the `ID` scalar as `string`; anything you pass here is merged on top.

```ts
airplane: {
  codegen: {
    scalars: { DateTime: 'string' },
    avoidOptionals: true
  }
}
```

## Runtime config

`endpoint` and `dbName` are exposed as `runtimeConfig.public.airplane`, so they can be overridden with `NUXT_PUBLIC_AIRPLANE_ENDPOINT` at runtime.

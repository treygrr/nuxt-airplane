`nuxt-offline` is a Nuxt module for apps that must keep working without a connection. You give it a GraphQL endpoint and your `.gql` files; it gives you typed composables whose data comes from a local database rather than from the network.

## How it works

::steps{level="3"}

### Operations become composables

Every named operation in your documents is registered under its name. `useQuery('GetSites')` and `useMutation('RenameSite')` are typed from the schema, so a typo in the name or in the variables is a compile error.

### Responses live in IndexedDB

Query responses are cached with [Dexie](https://dexie.org). `useQuery` returns **live data from that cache**: a cached result renders immediately, a refetch runs in the background when online, and anything that edits the cache updates every component reading it.

Out of the box each response is one cached row. Opt a query into [your own tables](/guide/stores-and-query-handlers) with `defineOfflineStores` and `defineQueryHandlers` to keep data normalized and queryable offline.

### Mutations apply locally and queue

`mutate()` runs your `apply` handler against the cache, stores the mutation and its variables in an outbox, and resolves. A sync loop sends the queue to the server in order whenever the app is online.

### Pending changes can be rolled back

Until a mutation has reached the server it can be undone. The rows it touched are restored and any later pending mutations are replayed on top.

::

## What you write

```graphql [app/graphql/sites.gql]
query GetSites {
  sites { id name archived }
}

mutation RenameSite($id: ID!, $name: String!) {
  renameSite(id: $id, name: $name) { id name }
}
```

```ts [app/offline/sites.ts]
export default defineMutationHandlers({
  RenameSite: {
    apply: ({ cache, variables }) =>
      cache.update('GetSites', (data) => {
        const site = data.sites.find(s => s.id === variables.id)
        if (site) site.name = variables.name
      })
  }
})
```

```vue [app/pages/sites.vue]
<script setup lang="ts">
const { data, loading } = useQuery('GetSites')
const rename = useMutation('RenameSite')
const { online, pending } = useSync()
</script>
```

## What you get

- `useQuery(name, variables?)` — see [Queries](/guide/queries)
- `useMutation(name)` — see [Mutations](/guide/mutations)
- `defineMutationHandlers()` — see [Mutation handlers](/guide/mutation-handlers)
- `defineOfflineStores()` and `defineQueryHandlers()` — see [Stores and query handlers](/guide/stores-and-query-handlers)
- `useSync()` — see [Sync and offline](/guide/sync-and-offline)
- Generated TypeScript types — see [Type generation](/guide/type-generation)

::note
The module runs entirely on the client. During server-side rendering `useQuery` returns `loading: true` with no data, and the page hydrates from IndexedDB in the browser.
::

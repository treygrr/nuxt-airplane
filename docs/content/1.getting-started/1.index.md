`nuxt-airplane` is a Nuxt module for apps that must keep working without a connection. You give it a GraphQL endpoint and your `.gql` files; it gives you typed composables whose data comes from a local database rather than from the network.

## How it works

::steps{level="3"}

### Operations become composables

Every named operation in your documents is registered under its name. `useQuery('GetSites')` and `useMutation('RenameSite')` are typed from the schema, so a typo in the name or in the variables is a compile error.

### Data lives in IndexedDB tables

Every type your documents select with an `id` gets a [table inferred from them](/guide/stores-and-query-handlers), typed from the schema, in a [Dexie](https://dexie.org) database. A query handler writes a response into the tables with `store` and builds the query's result from them with `read`. `useQuery` returns **what `read` returns, live**: stored data renders immediately, a refetch runs in the background when online, and anything that edits a row updates every component reading it.

### Mutations apply locally and queue

`mutate()` runs your `apply` handler against the tables, stores the mutation and its variables in an outbox, and resolves. A sync loop sends the queue to the server in order whenever the app is online.

### Pending changes can be rolled back

Until a mutation has reached the server it can be undone. The rows it touched are restored and any later pending mutations are replayed on top.

::

## What you write

```graphql [app/graphql/sites.gql]
query GetSites {
  sites { id name archived }
}

mutation RenameSite($id: ID!, $name: String!) {
  renameSite(id: $id, name: $name) { id name }
}
```

```ts [app/airplane/sites.ts]
export default defineQueryHandlers({
  GetSites: {
    store: ({ db }, data) => db.Site.bulkPut(data.sites),
    read: async ({ db }) => ({ sites: await db.Site.toArray() }),
  }
})
```

```ts [app/airplane/mutations.ts]
export default defineMutationHandlers({
  RenameSite: {
    apply: ({ db, variables }) => db.Site.update(variables.id, { name: variables.name })
  }
})
```

```vue [app/pages/sites.vue]
<script setup lang="ts">
const { data, loading } = useQuery('GetSites')
const rename = useMutation('RenameSite')
const { online, pending } = useSync()
</script>
```

## What you get

- `useQuery(name, variables?)` — see [Queries](/guide/queries)
- `useMutation(name)` — see [Mutations](/guide/mutations)
- `defineQueryHandlers()` and `defineAirplaneStores()` — see [Stores and query handlers](/guide/stores-and-query-handlers)
- `defineMutationHandlers()` — see [Mutation handlers](/guide/mutation-handlers)
- `useSync()` — see [Sync and offline](/guide/sync-and-offline)
- Generated TypeScript types — see [Type generation](/guide/type-generation)

::note
The module runs entirely on the client. During server-side rendering `useQuery` returns `loading: true` with no data, and the page hydrates from IndexedDB in the browser.
::

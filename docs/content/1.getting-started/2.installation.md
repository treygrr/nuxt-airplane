## Install the module

::code-group

```bash [npm]
npm install nuxt-airplane
```

```bash [pnpm]
pnpm add nuxt-airplane
```

```bash [yarn]
yarn add nuxt-airplane
```

::

## Register it

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-airplane'],
  airplane: {
    endpoint: 'https://api.example.com/graphql'
  }
})
```

`endpoint` is the only option you need. See [Configuration](/getting-started/configuration) for the rest.

## Add your documents

Put your operations in `.gql` or `.graphql` files anywhere under `app/`. Each operation must be named; fragments can live in any file.

```graphql [app/graphql/sites.gql]
fragment SiteFields on Site {
  id
  name
  archived
}

query GetSites {
  sites { ...SiteFields }
}

mutation ArchiveSite($id: ID!) {
  archiveSite(id: $id) { ...SiteFields }
}
```

## Use them

```vue [app/pages/index.vue]
<script setup lang="ts">
const { data, loading } = useQuery('GetSites')
const archive = useMutation('ArchiveSite')
</script>

<template>
  <p v-if="loading">Loading…</p>
  <ul v-else>
    <li v-for="site in data?.sites" :key="site.id">
      {{ site.name }}
      <button @click="archive.mutate({ id: site.id })">Archive</button>
    </li>
  </ul>
</template>
```

Start the dev server and the module introspects your endpoint to generate types for every operation. Without a handler the archive mutation still queues and syncs; it just won't show in the list until the next refetch. [Mutation handlers](/guide/mutation-handlers) make it appear immediately.

::tip
The repository ships a playground with an in-memory Apollo server and a sites/items inventory demo. Run `npm run dev` at the repository root and open `http://localhost:3000`.
::

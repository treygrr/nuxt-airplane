## Install the module

::code-group

```bash [npm]
npm install @treygrr/nuxt-airplane
```

```bash [pnpm]
pnpm add @treygrr/nuxt-airplane
```

```bash [yarn]
yarn add @treygrr/nuxt-airplane
```

::

## Register it

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@treygrr/nuxt-airplane'],
  airplane: {
    endpoint: 'https://api.example.com/graphql'
  }
})
```

`endpoint` is the only option you need. See [Configuration](/getting-started/configuration) for the rest.

## Add your documents

Put your operations in `.gql` or `.graphql` files anywhere under `app/`. Each operation must be named; fragments can live in any file.

```graphql [app/graphql/sites.gql]
fragment SiteFields on Site {
  id
  name
  archived
}

query GetSites {
  sites { ...SiteFields }
}

mutation ArchiveSite($id: ID!) {
  archiveSite(id: $id) { ...SiteFields }
}
```

## Use them

```vue [app/pages/index.vue]
<script setup lang="ts">
const { data, loading } = useAirplaneQuery('GetSites')
const archive = useMutation('ArchiveSite')
</script>

<template>
  <p v-if="loading">Loading…</p>
  <ul v-else>
    <li v-for="site in data?.sites" :key="site.id">
      {{ site.name }}
      <button @click="archive.mutate({ id: site.id })">Archive</button>
    </li>
  </ul>
</template>
```

Start the dev server and the module introspects your endpoint to generate types for every operation. Without a handler the archive mutation still queues and syncs; it just won't show in the list until the next refetch. [Mutation handlers](/guide/mutation-handlers) make it appear immediately.

## Scaffold the handlers

Handlers are what make a query work offline and a mutation show at once. To start from a file per operation instead of an empty folder, turn on [`handlers.generate`](/getting-started/configuration#handlersgenerate):

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@treygrr/nuxt-airplane'],
  airplane: {
    handlers: { generate: true },
  },
})
```

The next time the app starts, each operation without a handler gets a file with its hooks in place and their bodies empty: `app/airplane/queries/get-sites.ts` and `app/airplane/mutations/archive-site.ts` for the operations above. Fill them in as described in [Stores and query handlers](/guide/stores-and-query-handlers) and [Mutation handlers](/guide/mutation-handlers). Files that exist are never overwritten, and operations you add later are scaffolded as you save the `.gql` file.

A scaffolded query handler has a `read` that returns nothing yet, so its query shows nothing until you fill it in.

::tip
The repository ships a playground: Toolshed, a hardware store with inventory management, on an in-memory Apollo server, built with Vuetify. Its lab page (`/dev`) makes the server misbehave (dropped connections, lost answers, expired sessions, rate limits) and puts load on the client. Run `npm run dev` at the repository root and open `http://localhost:3000`.
::

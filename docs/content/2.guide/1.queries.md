`useQuery` takes the name of a query document and returns reactive refs backed by the IndexedDB cache.

```vue
<script setup lang="ts">
const { data, loading, fetching, error, updatedAt, refresh } = useQuery('GetSites')
</script>
```

## Where the data comes from

`data` is not the network response. It is a live view of the cache row for this query and these variables:

1. On mount the composable subscribes to the cache row with Dexie's `liveQuery`. If the row exists, `data` is set immediately and `loading` becomes `false`.
2. If the app is online, a request is sent in the background. The response is written to the cache, which updates `data`.
3. Any later write to that row — a refetch, or a [mutation handler](/guide/mutation-handlers) calling `cache.update('GetSites', …)` — updates `data` too.

This is what makes optimistic updates free: a handler edits the cache once and every component showing that query re-renders.

## Variables

Variables can be a plain object, a ref or a getter. When they change the composable switches to the matching cache row and fetches it.

```ts
const siteId = ref('site-1')
const { data } = useQuery('GetSite', () => ({ id: siteId.value }))
```

Each distinct set of variables has its own cache row. `undefined`, `null` and `{}` are treated as the same, empty set.

## Options

```ts
useQuery('GetSites', undefined, { fetch: false })
```

| Option | Default | |
| --- | --- | --- |
| `fetch` | `true` | Set to `false` to only read the cache and never hit the network. |

## Return value

| Field | Type | |
| --- | --- | --- |
| `data` | `Ref<Result \| null>` | Live data from the cache. |
| `loading` | `Ref<boolean>` | `true` until the cache has been read and, if online, the first fetch is done. |
| `fetching` | `Ref<boolean>` | `true` while a request is in flight. |
| `error` | `Ref<Error \| null>` | The last fetch error. |
| `updatedAt` | `Ref<number \| null>` | When the cached data was last fetched from the server. |
| `refresh` | `() => Promise<void>` | Fetch now. Does nothing while offline. |

## Offline behaviour

While [offline](/guide/sync-and-offline), `refresh` is a no-op and `loading` stays `true` only if nothing is cached yet. Showing `updatedAt` is a good way to tell users how fresh the data is.

## Server-side rendering

The cache lives in the browser, so during SSR `useQuery` returns `data: null` and `loading: true`. The initial fetch is deferred to `onMounted` so the client's first render matches the server's.

`useQuery` takes the name of a query document and returns reactive refs backed by the tables in IndexedDB.

```vue
<script setup lang="ts">
const { data, loading, fetching, error, updatedAt, refresh } = useQuery('GetSites')
</script>
```

## Where the data comes from

`data` is not the network response. It is what the query's [`read` handler](/guide/stores-and-query-handlers) builds from the tables, kept live:

1. On mount the composable runs `read` inside Dexie's `liveQuery`. If the query has been fetched before, `data` is set immediately and `loading` becomes `false`.
2. If the app is online, a request is sent in the background. The response goes through the query's `store` handler into the tables, and `read` runs again.
3. Any later write to a table `read` touched — a refetch, or a [mutation handler](/guide/mutation-handlers) editing a row — updates `data` too.

This is what makes optimistic updates free: a handler edits a row once and every component showing a query that reads it re-renders.

A query without a `read` handler is served from the network: `data` is the last response while online, and `null` with an `error` while offline.

## Variables

Variables can be a plain object, a ref or a getter. When they change the composable runs `read` with the new ones and fetches them.

```ts
const siteId = ref('site-1')
const { data } = useQuery('GetSite', () => ({ id: siteId.value }))
```

Each distinct set of variables is fetched and recorded on its own. `undefined`, `null` and `{}` are treated as the same, empty set.

## Options

```ts
useQuery('GetSites', undefined, { fetch: false })
```

| Option | Default | |
| --- | --- | --- |
| `fetch` | `true` | Set to `false` to only read the tables and never hit the network. |

## Return value

| Field | Type | |
| --- | --- | --- |
| `data` | `Ref<Result \| null>` | Live data from the tables. |
| `loading` | `Ref<boolean>` | `true` until the tables have been read and, if online, the first fetch is done. |
| `fetching` | `Ref<boolean>` | `true` while a request is in flight. |
| `error` | `Ref<Error \| null>` | The last fetch error. |
| `updatedAt` | `Ref<number \| null>` | When this query was last fetched from the server. |
| `refresh` | `() => Promise<void>` | Fetch now. Does nothing while offline. |

## Offline behaviour

While [offline](/guide/sync-and-offline), `refresh` is a no-op and `loading` stays `true` only if the query has never been fetched. Showing `updatedAt` is a good way to tell users how fresh the data is.

## Server-side rendering

The tables live in the browser, so during SSR `useQuery` returns `data: null` and `loading: true`. The initial fetch is deferred to `onMounted` so the client's first render matches the server's.

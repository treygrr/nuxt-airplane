Requests to the endpoint are configured with `defineAirplaneRequest`, in a file under `app/airplane/` like the handlers.

```ts [app/airplane/request.ts]
export default defineAirplaneRequest({
  headers: () => {
    const token = useCookie('token')
    return token.value ? { Authorization: `Bearer ${token.value}` } : {}
  },
  onResponse(response) {
    if (response.status === 401) navigateTo('/login')
  },
})
```

## Example: a protected API, end to end

Say your API is `https://api.example.com/graphql`, every request needs `Authorization: Bearer <token>`, and introspection is only allowed with a service token. Here is the whole setup.

::steps{level="3"}

### Configure the endpoint

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-airplane'],
  airplane: {
    endpoint: 'https://api.example.com/graphql',
    // Build-time introspection only. Read on the server, never shipped.
    schemaHeaders: { Authorization: `Bearer ${process.env.GRAPHQL_INTROSPECTION_TOKEN}` },
    // Wipe cached data on each deploy
    cacheKey: process.env.GIT_SHA,
  },
})
```

```dotenv [.env]
GRAPHQL_INTROSPECTION_TOKEN=svc_xxx
```

If introspection is disabled on the API, drop `schemaHeaders` and point `schema` at an SDL file instead: `schema: './schema.graphql'`.

### Send the user's token with every request

```ts [app/airplane/request.ts]
export default defineAirplaneRequest({
  headers: () => {
    const token = useCookie('auth-token')
    return token.value ? { Authorization: `Bearer ${token.value}` } : {}
  },

  async onResponse(response) {
    if (response.status === 401) {
      // The token is no longer valid: forget it and send the user to sign in.
      useCookie('auth-token').value = null
      await navigateTo('/login')
    }
  },
})
```

`headers` runs for each request, so whatever is in the cookie at that moment is what gets sent, including for mutations the sync loop sends later.

### Set the token at sign-in

How you obtain the token is up to you; the only requirement is that it ends up where `headers` reads it. With a plain login endpoint:

```vue [app/pages/login.vue]
<script setup lang="ts">
const email = ref('')
const password = ref('')
const token = useCookie('auth-token', { maxAge: 60 * 60 * 24 * 30, sameSite: 'lax' })

async function signIn() {
  const { accessToken } = await $fetch<{ accessToken: string }>('https://api.example.com/auth/login', {
    method: 'POST',
    body: { email: email.value, password: password.value },
  })
  token.value = accessToken

  // Anything the API rejected while signed out: re-queue it and send with the new token.
  const { pending, retry, sync } = useSync()
  for (const m of pending.value) if (m.status === 'failed') await retry(m.id)
  await sync()

  await navigateTo('/')
}
</script>
```

### What happens to queued work

A mutation queued offline is sent when the connection returns, with whatever token the cookie holds *then*. If the API rejects it (expired token → 401), the mutation is parked as `failed` in the outbox with its error; nothing is lost, and `onResponse` runs so you can send the user to sign in. The retry loop in the sign-in handler above re-queues those and syncs with the fresh token.

### Cookie sessions instead of tokens

If the API uses an HTTP-only session cookie, there is no token to read; just let the browser send the cookie:

```ts [app/airplane/request.ts]
export default defineAirplaneRequest({
  credentials: 'include',
  onResponse: async (res) => { if (res.status === 401) await navigateTo('/login') },
})
```

The API must allow it: `Access-Control-Allow-Credentials: true` and an explicit `Access-Control-Allow-Origin` (not `*`) for your app's origin.

::

## Dynamic headers

`headers` can be a plain object or a function. The function runs **for every request**, inside the Nuxt app context, so composables such as `useCookie`, `useState` or a Pinia store work in it. It can be async (refresh an expiring token first).

That matters more here than in an online-only app: a mutation queued offline is sent by the sync loop whenever the connection returns, which may be hours later. Because the headers are computed at send time, it goes out with the token that is valid *then*, not the one that was valid when the user clicked.

The function receives what is being sent, if you need to vary headers per operation:

```ts
headers: ({ document, kind, variables }) =>
  kind === 'mutation' ? { 'x-idempotency-key': hashOf(document, variables) } : {}
```

## Cookie auth

For cookie sessions on another origin, set `credentials`:

```ts
export default defineAirplaneRequest({ credentials: 'include' })
```

## Reacting to responses

`onResponse` is called with the raw `Response` before it is parsed, for every query and queued mutation. Typical uses: sign the user out on `401`, hold the client offline on `503` with `useSync().goOffline()`, or log request ids.

A rejected queued mutation (GraphQL errors in the body) is parked as `failed` in the outbox as usual; `onResponse` only adds a place to react to the HTTP layer.

## Timeouts

Every request is aborted after `timeout` milliseconds (default 30 000). Without it, a request that never settles would keep the sync loop waiting for the rest of the session. Raise it for slow mutations, or lower it on flaky connections so the queue moves on to retry sooner.

```ts
export default defineAirplaneRequest({ timeout: 10_000 })
```

## Custom fetch

Pass `fetch` to route requests through your own implementation, for instance `ofetch`'s `$fetch.native`, or a wrapper that retries or signs requests.

## Static headers

Headers that never change can live in the module options. They are public runtime config, shipped to the browser, so this is for API keys you'd expose anyway, not secrets.

```ts [nuxt.config.ts]
airplane: {
  endpoint: 'https://api.example.com/graphql',
  headers: { 'x-api-key': 'public-key' },
}
```

They apply first; `defineAirplaneRequest` headers are merged on top and win on conflicts.

## Build-time introspection

Type generation introspects the endpoint at build time. If that needs auth, use `schemaHeaders`; it is read on the server during the build and never shipped.

```ts [nuxt.config.ts]
airplane: {
  endpoint: 'https://api.example.com/graphql',
  schemaHeaders: { Authorization: `Bearer ${process.env.GRAPHQL_INTROSPECTION_TOKEN}` },
}
```

Or point [`schema`](/getting-started/configuration#schema) at an SDL file and skip introspection altogether; many production APIs disable introspection anyway.

::tip
The playground's `/api/graphql` rejects requests without a bearer token; `app/airplane/request.ts` sends one. Its types come from an SDL file (`schema`), so no introspection token is needed; drop the `schema` option to see introspection with `schemaHeaders` instead.
::

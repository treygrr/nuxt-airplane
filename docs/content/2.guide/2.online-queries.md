Some queries have nothing worth keeping offline: search suggestions, a report, live prices. `useOnlineQuery` asks the server and shows what it answers, and does nothing else. It needs no handler and never touches the tables.

```vue
<script setup lang="ts">
const term = ref('')
const { data, error, fetching, refresh } = useOnlineQuery(
  'Search',
  () => ({ term: term.value }),
  { enabled: () => term.value.length >= 2 },
)
</script>
```

Use [`useAirplaneQuery`](/guide/queries) when the data should be there offline and follow local changes; use `useOnlineQuery` when the server's answer is all there is.

## When it asks

- When the component is set up, and whenever the variables change. Variables are compared by value: a getter that builds a new object with the same contents every time asks once.
- When `enabled` becomes `true`. While it is `false` nothing is sent, and `data` keeps the last answer, so a search box that drops under two characters does not blank its list.
- When the app comes back online, if the last run was skipped offline or got no answer from the network. Pass `refetchOnReconnect: false` to wait for the next change instead.
- After a sync, when a synced mutation names it in its [`refetch`](/guide/mutation-handlers#refetch) list. Nothing else a mutation changed says anything about an online query, so it is not asked again otherwise.
- When you call `refresh()`.

Only the latest request counts: if the user types faster than the server answers, a slow answer to an older term never replaces a newer one. Components asking for the same variables at the same moment share one request.

## Errors and offline

An error sets `error` and keeps the last `data`; the next answer clears it. `error` is:

- a `GraphQLRequestError` when the server answered with errors,
- an error with a `status` when it answered with an HTTP error,
- anything else when no answer arrived (the network, a timeout),
- an `OfflineError` when the app was [offline](/guide/sync-and-offline), by the network or by `goOffline()`. Nothing is sent then.

A run the network or being offline kept from an answer is made up when the app is back online. One the server answered, with data or errors, is not.

## Server-side rendering

While Nuxt renders a page on the server, `useOnlineQuery` asks there, and the answer goes to the browser in the page. The first render already has `data`, and the browser does not ask again until something changes.

How the server reaches the endpoint:

- **A path in your app** (`/api/graphql`) is answered in the same process, with the visitor's cookies and `authorization` header passed on, as the browser would send them.
- **A URL elsewhere** is fetched with nothing of the visitor's added: their cookies belong to your app, not to that API. Send what it needs from [`defineAirplaneRequest`](/guide/auth-and-headers#on-the-server).

Your `defineAirplaneRequest` options apply on the server too: `headers` runs there, inside the Nuxt app, so `useCookie` reads the visitor's cookie. Only the files that `export default defineAirplaneRequest(…)` are loaded on the server; your query and mutation handlers never are.

An error on the server is final: the page renders with it, and the browser shows the same error without asking again. A request takes at most [`timeout`](/guide/auth-and-headers#timeouts) (30 seconds by default), which bounds how long it can hold up the page.

Pass `server: false` to ask only in the browser, for example when the token lives only there. The page then renders with `fetching: true` and no data.

::warning
An answer rendered on the server is part of the page's HTML, and it is the visitor's own. Do not cache such pages publicly. See [Security](/guide/security#network).
::

## Options

| Option | Default | |
| --- | --- | --- |
| `enabled` | `true` | A boolean, ref or getter. Nothing is sent while it is `false`. |
| `refetchOnReconnect` | `true` | Ask again on reconnect after a run the network or being offline kept from an answer. |
| `server` | `true` | Ask while rendering on the server, and hand the answer to the browser in the page. |

## Return value

| Field | Type | |
| --- | --- | --- |
| `data` | `Ref<Result \| null>` | The last answer. Kept through errors, while not enabled, and while new variables are on their way. |
| `error` | `Ref<Error \| null>` | Why the last run has no answer. |
| `fetching` | `Ref<boolean>` | `true` while a request is on its way. |
| `updatedAt` | `Ref<number \| null>` | When `data` came from the server. |
| `refresh` | `() => Promise<void>` | Ask now. Does nothing while not enabled. |

## What it never does

- Store the answer, or write a fetch record, even when the query has a handler.
- Show anything offline it has not already shown.
- Hold a page up past its timeout, or fail one: a failed query renders with its error.
